# Editorial Radar Shell Design

## Goal

把现有图形化界面从“功能菜单集合”重组为一个低密度、编辑部气质的个人情报产品。第一阶段聚焦核心路径：打开首页看到今日判断，进入重点详情，继续阅读，生成简报，追踪主题，必要时管理信源。

## Product Direction

用户已确认的方向：

- 产品定位：个人情报台。
- 首页排序：混合推荐，综合跨源共识、突发加速和个人相关性。
- 首页性格：判断型首页，而不是文章流或后台仪表盘。
- 改版范围：首页 + 核心路径。
- 视觉气质：编辑部感。
- 主动作：继续阅读。
- 按钮体系：不用蓝色主按钮；主操作黑底白字，次级操作浅底描边。

## Non-Goals

- 第一阶段不重写所有页面。
- 不把信源健康、队列、运营指标放回首页。
- 不把首页做成长列表、统计大屏或后台控制台。
- 不改变现有抓取、富化、聚类、日报生成和发布后端通路。

## Information Architecture

左侧导航从十多个功能入口收敛成五个产品区：

1. `Today`
   - 默认首页。
   - 展示 Editorial Radar、今日主焦点、今日 5 个重点。
   - 承接主焦点详情抽屉。

2. `Read`
   - 阅读与回看区。
   - 包含全部文章流、搜索、收藏、主题详情、代表来源和同簇文章。
   - 承接首页的“继续阅读”。

3. `Briefs`
   - 内容产出区。
   - 包含日报列表、新建简报、微信公众号草稿工作流、发布尝试记录、写作风格学习。
   - 承接首页和详情抽屉里的“生成简报”。

4. `Sources`
   - 信源管理区。
   - 包含信源库、推荐信源、博主订阅、信源健康、去重/合并、抓取质量。
   - 承接详情里的“查看来源”和低频管理任务。

5. `Settings`
   - 低频配置区。
   - 包含 AI 模式、发布渠道、安全/访问控制、运营工具入口。

## Today Page

首页首屏只保留四层信息：

1. 日期与总判断
   - 示例：`今天有 5 个信号值得注意`
   - 辅助文案解释排序依据：跨源共识、突发加速、个人关注方向。

2. Main Signal
   - 展开今日最重要的一件事。
   - 使用编辑部标题风格，强调判断而不是罗列。
   - 包含 1 段短判断：为什么重要、影响什么、证据强度如何。

3. 上榜理由
   - 三个低饱和标签：
     - 共识：来源覆盖数量或跨平台覆盖。
     - 突发：短时间升温、burst velocity 或 breaking score。
     - 相关：命中用户关注、收藏、关键词、AI/产品方向。

4. 次重点
   - 只露出其余 4 个标题。
   - 不在首页展开摘要、来源列表和时间线。

首页主按钮是黑底 `继续阅读`。`生成简报`、`追踪主题`、`查看来源` 是次级按钮。

## Main Signal Drawer

点击 `继续阅读` 打开详情抽屉，而不是跳转到复杂页面。抽屉承接深度信息，保持首页低密度。

左侧内容：

- Main Signal 标题。
- 编辑判断段落。
- 三个信号卡：Consensus、Velocity、Relevance。
- 代表来源列表：来源名、文章标题、一句话摘要。
- 简短时间线：信号首次出现、多源覆盖、进入主焦点。

右侧操作：

- 黑底主按钮：生成简报段落。
- 次级按钮：追踪这个主题、收藏代表文章。
- `为什么给我看`：解释个人相关性。
- 相关主题标签。

抽屉规则：

- 左侧解释判断和证据。
- 右侧承接操作和个性化解释。
- 不把所有原始文章一次性展开；最多展示代表来源，完整列表进入 `Read`。

## Visual Rules

整体气质：

- 编辑部感，偏简报和阅读桌面。
- 克制、低密度、少滚动。
- 背景可使用暖白或纸面感，但避免一整套米色导致单调；用深墨色、灰褐色和少量低饱和状态色建立层级。

按钮：

- 主操作：黑底白字。
- 次级操作：浅底描边。
- 危险操作：只在管理/设置场景使用红色。
- 不使用蓝色主按钮。

排版：

- 首页允许使用 serif 字体做关键标题，正文和工具控件继续使用 sans-serif。
- 第一屏标题大，但卡片、抽屉和导航里的字号保持克制。
- 不使用大面积营销 hero，不做装饰性渐变和光斑。

组件：

- Card 只用于具体条目或抽屉内信息块，不做层层嵌套。
- 首页主区域用 section、分隔线和留白建立层级。
- 状态信号用标签或小信息块，不用大型 KPI 面板。

## Existing Data Mapping

Today 首页可复用现有能力：

- `getHotspotOverview` / `/api/stats`
  - consensusClusters
  - breakingClusters
  - keywordGroups
  - hotspot indexes

- `listItems` / `/api/items`
  - 代表文章。
  - 文章流和 Read 区。

- `listClusterSiblingItems`
  - Main Signal 抽屉里的代表来源和同簇文章。

- `reports` engine
  - Briefs 区和“生成简报”动作。

第一阶段不要求新增后端模型。若个人相关性不足，可以先用现有标签、收藏、关键词和来源 scope 做规则解释。

## Phase 1 Scope

第一阶段交付：

- 新导航信息架构：Today / Read / Briefs / Sources / Settings。
- Today 首页重构为 Editorial Radar Shell。
- Main Signal 详情抽屉。
- 将现有页面入口归并到对应产品区。
- 按钮和视觉规则统一。

保留现有页面能力：

- 原 `/sources`、`/recommended-sources`、`/creators`、`/health` 迁移到 Sources 区入口。
- 原 `/reports` 迁移到 Briefs 区入口。
- 原时间线、搜索、收藏迁移到 Read 区入口。
- 原 `/settings` 和 `/ops` 放入 Settings 区。

## Acceptance Criteria

- 首屏不出现长时间线、信源健康表、队列状态或大统计面板。
- 用户 10 秒内能看到一个明确今日判断和一个主焦点。
- 主焦点能解释为什么上榜，而不是只展示分数。
- 点击继续阅读后可以看到代表来源、时间线和相关操作。
- 生成简报、追踪主题、查看来源都能从主链路自然进入。
- 主按钮为黑色，不出现蓝色主按钮。
- 现有核心功能仍可通过二级区访问。
